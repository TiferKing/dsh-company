# 项目梳理与修复记录

日期：2026-09-05。以本次开始时的工作区内容为基础，保留已有未提交修改。本文记录本轮审查的发现；核心运行说明见 [架构文档](architecture.md)。

## 已修复的问题

| 范围 | 原有问题 | 修复后的行为 |
|---|---|---|
| 工作调度 | 耗尽尝试的 pending 工作仍被选中，后续工作饥饿 | 选择器跳过耗尽尝试的工作 |
| 工作结果 | 分步更新覆盖已提交证据、评审 verdict | 省略字段保留原值，终态校验合并后的记录 |
| 冷恢复 | 过期租约可能撤销运行中尝试或丢失已接受进度 | 区分尚未投递与已接受的尝试，核对实际会话状态 |
| 会话竞争 | 旧会话 idle 事件可能释放替代会话预算 | 状态事务重新核对 session ID |
| 重试可达性 | 传输失败和 HR 冷却依赖下一条外部事件 | 每工作区一个可合并的延迟唤醒，卸载时清理 |
| 消息交付 | 缺少预算被计为投递失败，消息永久失效 | 保留 held_budget，补充资源后仍可投递 |
| 坏会话 | work/HR 对不可恢复会话持续重试 | 标记 failed、撤销失效支持指派并通知 Founder |
| 请求准入 | 残留预留可能让暂停或受阻员工继续请求 | 根据新事务中的阶段、状态和创建 generation 重新准入 |
| 事实记账 | 迟到用量可能归新工作、消耗新预留 | 绑定请求时的预留、工作、产品、价格与授权使用记录 |
| 历史回放 | 新预留或当前 fallback 被当作历史路线依据 | 无法确定时保留 unknown cost，员工暂停复核 |
| 员工退休 | 退休期间最后一笔用量可能丢失 | 已发起调用的事实费用继续记账 |
| 超支处置 | 员工只被标记 paused，实际执行未中断；HR 租约残留 | 实际中断并一致回收预留、工作和评估状态 |
| 金额计算 | 大预算低单价时中间整数超出 Number 安全范围 | 先在 BigInt 中按上下文上限约束，再转换 |
| HR 继任 | 恢复路径修改旧快照；已接受评估预留可能残留 | 在新事务中交接权限，按账本中的请求归属释放预留 |
| 恢复竞争 | 重复 root 恢复并行推进同一人事操作 | 合并同一 Founder 的在途恢复 |
| 审批一致性 | 直接处理已过期 HR 审批时建议未同步结束 | 审批与 staffing 状态同步过期处理 |
| 发布门槛 | 缺少作者或跨产品关系可能被算成独立评审 | 明确双方作者、同一产品与已完成状态 |
| 归档 | 指定支持员工或未结工单导致聚合校验失败 | 撤销支持指派、关闭工单并明确取消未完修复 |
| 归档竞争 | 等待员工停止期间新增工作可能被无批准取消 | 锁内复核公司身份、未完工作和精确批准理由 |
| 存储创建 | 对尚未成立的公司执行事务留下空 active 目录 | 缺失状态直接失败，不阻塞随后成立公司 |
| Web 来源判断 | 代理链只检查首跳，可被伪造回环首跳绕过 | 校验地址格式及完整 Forwarded/X-Forwarded-For 链 |
| Web 缓存 | 切回会话无快照却携带 ETag，动态状态不刷新 | 验证器与有效快照绑定，摘要包含实际投影 |
| Web 并发 | 动作期间的旧 GET 可能覆盖新状态 | 成功动作后的刷新取消旧读取 |
| 快照裁剪 | 保留的授权记录可能引用已裁掉的退休员工 | 员工保留窗口优先保留可见审计所需引用 |
| 模型探测 | 取消被当成能力失败，适配器无响应时无法结束等待 | 取消不提交目录；调度卸载信号贯穿探测 |
| 模型工具输出 | company_status 超过 20k 字符被截成无效 JSON，预算和审批不可见 | 默认概览，提供分区、筛选与分页详情 |
| 协作指令 | 消息一律不得触发行动，与增员/阻塞上报冲突 | 消息是待评估提案，经正式状态与治理流程响应 |

## 兼容性与尚存边界

- `company_status` 的默认工具结果改为 overview。依赖旧完整 CompanySnapshot 的外部工具调用方需要改用 section 查询；HTTP schema-v5 保持不变。
- 本次没有改变磁盘 schema 或包版本，也没有发布、安装到运行中的 DSH 或改动实际公司数据。
- 员工共享工作目录；attempt 校验不等于文件写入隔离。当前交付证据由员工报告，插件不独立证明测试真实性。
- 外部效果描述尚未与具体云资源、终端命令逐项绑定；DSH 权限和工具审批仍负责实际执行边界。
- 长期用量仍存在全量聚合中，审计是有界窗口；没有跨主机调度或公网多租户认证。
